IronScheme
==========

IronScheme aims to be a R6RS conforming Scheme-like implementation for .NET.

IronScheme implements over 99% of the R6RS specification and specified behavior. 

IronScheme's macro expander (`src/scheme/boot/expander/`) is derived from psyntax, and thus behaves similar to other implementations using psyntax, ie Icarus, Vicare, Chez.

This branch replaces the DLR-based compiler with a [nanopass](https://github.com/nanopass/nanopass-framework-scheme) compiler written in Scheme that compiles straight to CIL. It bootstraps from a text seed using nothing but the .NET SDK. Full re-entrant `call/cc` is not supported (escape-only continuations). Design notes are in `designs/`.

Building
========

Requires only the .NET 10 SDK, on Windows, Linux and macOS.

```
git clone https://github.com/IronScheme/IronScheme.git -b master --recurse-submodules

cd IronScheme

dotnet build    # build everything, including the boot image src/scheme/boot/ironscheme.boot.dll
dotnet test     # build, then run all tests (add e.g. --filter TestCategory=Conformance)
```

The repository root holds `IronScheme.slnx` (C# projects in `src/`, tests in `tests/`, the Scheme sources in `src/scheme/`), and builds there default to Release. Under `src/scheme/`, `boot/` holds everything compiled into the boot image (core libraries, the macro expander, the primitive table, the seed and the build scripts), `lib/` holds the libraries loaded on demand (including the compiler), and `tests/` holds the Scheme test scripts. The boot image is generated by the `GenerateBootImage` target in `IronScheme.Hosting.csproj`, which runs stage0. This takes about 45 seconds and is skipped when the seed, the Scheme sources, the compiler and the C# runtime are unchanged. To build only the C# projects, pass `-p:BuildBootImage=false`.

Maintenance commands outside the normal build live in `tools/build.cs`, a .NET 10 file-based C# program, so no shell is needed:

```
dotnet run tools/build.cs -- stage1 <dir>      # build a boot image into another directory
dotnet run tools/build.cs -- seed [--stage0]   # regenerate the text seed
dotnet run tools/build.cs -- ilverify <dll>... # verify emitted assemblies (dotnet tool install -g dotnet-ilverify)
```

On Linux and macOS, `./tools/build.cs <command>` also works.

How the bootstrap works:

1. `IronScheme.Stage0` (a small C# interpreter for the core language) runs the text seed `src/scheme/boot/boot-seed.core`: the boot sources, the expander included, after macro expansion.
2. On stage0, `boot/ironscheme-buildscript-nano.sps` expands the boot sources, the nanopass framework and the compiler, then compiles them with the new compiler into Lcil (a text form of CIL). `IronScheme.Emit` assembles the Lcil into `ironscheme.boot.dll` (the `GenerateBootImage` build target).
3. The new system can rebuild itself to a fixpoint, so stage1, stage2 and stage3 are byte-identical (the `Bootstrap` tests). The `seed` command regenerates the text seed on the new system, or on stage0 with `--stage0`; both produce the same seed.

Running
=======

```
cd src/scheme
dotnet ../IronScheme.Host/bin/Release/net10.0/IronScheme.Host.dll -I lib            # REPL
dotnet ../IronScheme.Host/bin/Release/net10.0/IronScheme.Host.dll -I lib foo.sps    # run an R6RS program
```

In a terminal the REPL has line editing: history (Up/Down, saved to `~/.ironscheme_history`), Tab completion of names and of library names inside `(import ...)` (press Tab twice to list candidates), a dimmed parameter hint such as `(list-tail lst index)` after `(name `, and multi-line input that continues while parentheses are open. Ctrl+C cancels the current input and Ctrl+D (Ctrl+Z on Windows) on an empty line exits.

Options: `-I <dir>` adds a library search path, `--boot <dll>` selects the boot image, `--show-imports` prints the libraries as they load. When started from `src/scheme`, the host picks up a newer `boot/ironscheme.boot.dll` automatically.

Compiling libraries
===================

Like Chez Scheme, source files can be compiled ahead of time. The output is a `.fasl` file, which is a .NET assembly:

```scheme
(import (ironscheme))
(compile-library "demo/util.sls")      ; -> demo/util.fasl; imports of (demo util) now load it
(compile-program "app.sps")            ; -> app.fasl; run it with: IronScheme.Host app.fasl args...
(compile-file "x.ss")                  ; a library file or a top-level program, decided by its first form
(compile-imported-libraries #t)        ; also compile libraries loaded from source during compilation
(load "demo/util.fasl")                ; load compiled code in the REPL
```

A compiled program records the libraries it was compiled against. If one of them is expanded again from source (for example because its source became newer than its `.fasl`), the program reports that it needs to be recompiled.

Run `(compile-system-libraries)` from the REPL in `src/scheme` to precompile all bundled libraries (including SRFI and PFDS) to dlls.

Self-contained publishing
=========================

The target machine does not need .NET installed:

```
dotnet run tools/build.cs -- publish                                        # IronScheme itself: IronScheme.Host + lib/
dotnet run tools/build.cs -- publish examples/WordCount/wordcount.sps       # a standalone single-file application
artifacts/publish/wordcount-linux-x64/wordcount -n 5 README.md
```

When you publish an application, the program and every library it uses are compiled (`compile-whole-program`) and embedded together with the boot image, so the result is a single executable. Use `-r <RID>` to target another platform and `-o <dir>` to choose the output directory.

Embedding in C#
===============

Reference `src/IronScheme.Hosting`. The boot image and the `lib/ironscheme` sources are copied to your output directory.

```csharp
using IronScheme.Hosting;

SchemeRuntime.Initialize(new SchemeRuntimeOptions { LibraryPaths = { "scheme" } });
SchemeRuntime.Eval("(define (sq x) (* x x))");
var three = SchemeRuntime.Eval("(+ 1 2)");                                  // 3
var upper = SchemeRuntime.Eval("(string-upcase \"abc\")", "(rnrs)");          // evaluate under given imports
var find  = SchemeRuntime.GetFunction<Func<string, object>>("(bookstore)", "find-books");
```

Conditions raised by Scheme code surface as `SchemeError`, whose message is the printed condition. The runtime is not thread-safe, so serialize calls into Scheme.

`examples/WebServer` is a complete example. ASP.NET Core minimal API routes call the Scheme library `(bookstore)`, which uses `Microsoft.Data.Sqlite` from Scheme to query a SQLite database:

```
dotnet run --project examples/WebServer -c Release     # then open http://localhost:5000/
```

Running tests
=============

`dotnet test` in the repository root runs everything. The test categories are:

- `IronScheme.Core.Tests`: runtime, reader, emitter, stage0, compiler pass snapshots.
- `Bootstrap`: seed → stage0 → stage1 → stage2 → stage3, comparing Lcil and dlls and running ILVerify (`dotnet tool install -g dotnet-ilverify`).
- `Conformance`: the R6RS test suite (3 known failures), trig, CLisp number and floating-point tests.
- `SRFI`, `Other` (PFDS, MiniKanren, FFI, REPL completion hooks), `SystemLibraries` (compiles all libraries, loads them from dlls only, and runs ILVerify on them).
- `CompileFile` (`compile-file`, `compile-library`, `compile-program` and `.fasl` loading), `Examples` (starts the WebServer example and calls its API), `Hosting` (the embedding API, in process).

From the REPL, `(ironscheme-test)` runs the R6RS test suite.
